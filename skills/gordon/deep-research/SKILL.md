# deep-research

# 深度研究（Deep Research）

把深度研究作为可恢复的证据工作流执行。每次只推进一个明确步骤或一个小批次问题，并把状态写回文件。本技能不预设任何领域：报告骨架与问题拆解由研究主题本身驱动。

## 工作原则

- 先定义研究目标和问题，再检索；不要从宽泛搜索开始。
- 默认创建交付物后继续执行。仅当范围歧义会实质改变结论、用户要求审阅，或下一步涉及显著成本/外部动作时暂停。
- 每轮集中处理 1 个研究问题；高度相关时最多合并 2 个。完成证据记录、分析和清单更新后再处理下一批。
- 区分事实、推算、判断和未知。没有可靠证据时明确写“待验证”，不要补造数字或结论。
- 关键事实尽量使用两个独立来源交叉验证；统计数据、价格、法规、版本等时效性数据注明地区、口径和日期。
- 优先一手来源：官方文档、原始数据、公告与财报、论文、法律法规原文、产品官网、一手访谈/调查。二手来源用于发现线索和补充视角。
- 报告随研究渐进生长，不要等所有检索结束后一次性写完。

## 启动与目录

1. 从用户输入提取：研究主题、研究目标（要回答什么/支持什么决策）、受众、范围与边界、时间范围、限制条件、已有材料和成功标准。
2. 对缺失但不阻塞的信息作保守假设，并在 `00-研究简报.md` 中标注。只询问会显著改变研究边界的问题。
3. 运行初始化脚本自动创建工作区，避免手工复制模板带来的不一致：

   ```bash
   bash "<本技能目录>/scripts/init-workspace.sh" "<研究主题>" "<目标目录>"
   ```

   - `<本技能目录>` 指本 SKILL.md 所在目录；`<目标目录>` 默认当前工作目录。
   - 脚本在目标目录下创建 `deep-research-<主题>-<YYYYMMDD>/`，并一次性生成以下六个骨架文件（字段与表头已预填，后续只需在对应文件内渐进填写）：

   | 文件 | 用途 |
   |---|---|
   | `00-研究简报.md` | 目标、边界、假设、定义和交付标准 |
   | `01-研究问题.md` | 关键问题及优先级、判定标准 |
   | `02-检索方案.md` | 逐问题检索词、来源类型、取证目标 |
   | `03-研究报告.md` | 待填充框架，随研究渐进更新 |
   | `04-执行清单.md` | 唯一进度真相源 |
   | `05-证据台账.md` | 来源、数据、可信度、用途与冲突 |

   文件字段和质量标准见 [references/research-method.md](references/research-method.md)。

## 阶段 1：定义研究问题

先判断本次研究的**类型**，它会决定问题拆解的重点和报告骨架：

- **决策支持型**：帮助做一个选择（该不该做、选哪个、走哪条路）。
- **现状理解型**：搞清某主题的全貌、机制、现状与趋势。
- **对比评测型**：多个对象的横向对比与优劣判断。
- **方案设计型**：针对某问题给出可落地的解决方案。
- **事实核查型**：验证某个说法、数据或结论是否成立。

从研究目标出发拆解出必须回答的子问题。可借用通用拆解框架（启发式，非硬约束，按需取舍）：

- 边界与定义：研究对象是什么、范围划在哪；
- 现状与事实：现在是什么样；
- 机制与原因：为什么是这样；
- 主体与格局：涉及谁、相互关系如何；
- 影响与后果：会带来什么；
- 方案与路径：怎么办、有哪些选项；
- 风险与未知：哪里不确定、最坏情况是什么。

问题数量通常 6–12 个，按主题复杂度和决策粒度调整；太少覆盖不全，太多难以闭环。每题记录：

- 问题编号、问题本身；
- 为什么影响结论或决策；
- 所需证据或指标；
- 完成判定标准；
- 优先级 P0/P1/P2；
- 依赖与当前假设。

问题应可研究、可判定。把“了解一下 X”改成带边界、对象、指标或时间口径的具体问题。将问题写入 `01-研究问题.md`，同时在 `04-执行清单.md` 建立对应任务。

## 阶段 2：设计检索方案

为每个问题设计检索矩阵，不只列一串关键词。至少包含：

- 核心词：主题、对象、范围、指标；
- 同义词与上下位概念；
- 中英文检索式（如主题涉及）；
- 限定词：年份、报告、统计、官方文档、论文、数据、案例等；
- 建议来源和优先域名；
- 需要获得的具体数据或证据；
- 备用检索路径与停止条件。

将结果写入 `02-检索方案.md`。对数值/规模类问题同时设计自上而下和自下而上的取数路径；对观点/机制类问题同时覆盖正反两方证据；对对比类问题统一比较维度后再取数。

## 阶段 3：建立报告骨架

在检索前创建 `03-研究报告.md`。报告结构由研究类型和主题决定，不套用固定章节。通用骨架（可按需增删）：

1. 执行摘要与结论（最后定稿）
2. 研究范围、定义和方法
3. 主题主体内容（按研究问题组织）
4. 关键证据与分析
5. 风险、局限与反证
6. 结论、建议与下一步
7. 来源与附录

各类型可在此基础上调整：决策支持型强化“选项对比 + 决策结论”；现状理解型强化“机制 + 趋势”；对比评测型以“统一维度对比表”为核心；方案设计型强化“方案 + 落地步骤 + 验证”；事实核查型强化“逐条主张的成立/不成立判定”。

每个模块预先写明：要回答的问题、需要的数据、分析方法、图表/表格、当前证据状态和待办。不要预写未经支持的结论。

## 阶段 4：制定执行清单

按依赖和决策价值排序，而不是机械按报告章节排序。优先验证可能推翻结论的 P0 问题，再研究优化类问题。

每项任务包含：ID、对应问题、动作、预期产物、状态、证据门槛、依赖、下一动作。状态只使用 `待开始`、`进行中`、`受阻`、`待复核`、`完成`。

在文件顶部维护“当前焦点”“下一步”和“最近更新时间”。任何时候只能有一个当前焦点。

## 阶段 5：小批次执行闭环

对当前焦点重复以下闭环：

1. 读取 `04-执行清单.md`，选择最高优先级且无阻塞的一题。
2. 读取该题在 `02-检索方案.md` 中的检索式，先找高可信来源，再补充其他视角。
3. 每获得一条有用证据，立即写入 `05-证据台账.md`；保存可访问链接、标题、机构、发布日期、访问日期、适用范围和支持/反驳的主张。
4. 检查定义、口径、样本、时效、利益相关性和来源独立性。记录矛盾证据，不要静默择优。
5. 达到该题停止条件后，先写“问题结论卡”：简答、证据、推理、置信度、局限、剩余未知。
6. 只更新 `03-研究报告.md` 中受该证据影响的模块，并保留引用。
7. 更新 `01-研究问题.md` 的回答状态和 `04-执行清单.md` 的状态、阻塞项与下一动作。
8. 向用户简要汇报本轮新增结论、证据强度、文件变化和下一焦点，然后继续；若触发暂停条件则请求审阅。

不要在同一轮首次研究全部问题。若工具或时间受限，优先完成一个可闭环的问题，并确保文件足以让下一次会话继续。

## 阶段 6：综合与定稿

仅在所有 P0 问题完成或明确受阻后进行综合。执行：

- 对齐各问题之间的定义和假设，消除口径冲突；
- 将结论明确关联到证据和研究问题；
- 给出可决策的结论（如“推荐 A / 有条件采用 / 不采用”）及触发条件，或对现状给出明确的综合判断；
- 提供优先级建议、最小验证方案、关键指标和 30/60/90 天或分阶段下一步（如适用）；
- 对每个核心结论标注置信度，列出会推翻该结论的新证据；
- 清除无引用的重要事实、重复内容和占位符；
- 将清单任务标为完成或受阻，不把未知伪装成完成。

最终交付完整报告，并同时保留研究问题、检索方案、证据台账和执行清单，使过程可审计、可复用。

## 暂停条件

遇到以下情况暂停并请求用户决策：研究范围存在会改变结论的分叉；关键数据源不可访问或需付费；来源严重冲突且无法解释；结论触发重大法律、伦理或安全风险；用户明确要求每阶段审批。

暂停时仍需更新文件，写清阻塞原因、已尝试路径、可选方案及各自影响。
